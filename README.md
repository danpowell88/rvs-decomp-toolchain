# rvs-decomp-toolchain

The public toolchain of [`danpowell88/rvs-decomp`](https://github.com/danpowell88/rvs-decomp), the
Rainbow Six 3: Raven Shield decompilation. The build needs period compilers (Visual C++ .NET 2003 and
Visual C++ 6.0 SP5 + Processor Pack), SDK headers and libraries, and a few prebuilt third-party
files. Most of those files are already published, byte for byte, by other public projects; this
repository holds the files that have no such copy, one zip per toolchain piece, plus the manifest that
pins all of them.

No account, token or `gh` is needed to use it.

## How `fetch.ps1` uses it

`toolchain/fetch.ps1` in rvs-decomp reads `toolchain/manifest.json` (identical to `manifest.json`
here) and assembles every piece under `.toolchain\`:

1. **Public files** come from third-party public sources pinned in the manifest (`public` of each
   piece): release archives and commit archives (tar.gz / zip, the archive SHA-256 pinned) and single
   files from commit-pinned `raw.githubusercontent.com` prefixes (each file's SHA-256 is the pin).
2. **Everything else** comes from this repository's release
   [`toolchain-1`](https://github.com/danpowell88/rvs-decomp-toolchain/releases/tag/toolchain-1)
   (manifest `release_repo` and `release_tag`), downloaded by plain HTTPS:

   ```
   https://github.com/danpowell88/rvs-decomp-toolchain/releases/download/toolchain-1/<piece>.zip
   ```

   The zip's SHA-256 (`release.sha256` of the piece) is checked before the zip is opened; a mismatch
   fails the fetch. Only the rows marked `private` in rvs-decomp's `toolchain/files/<piece>.tsv` are
   taken from the zip (see "Zip contents" below).
3. Every installed file is then checked against its own SHA-256 in the files list.

```powershell
.\toolchain\fetch.ps1                                          # download (no token)
.\toolchain\fetch.ps1 -ToolchainRepo C:\src\rvs-decomp-toolchain   # offline: read assets\*.zip from a checkout
```

`-ToolchainRepo` (or `$env:RVS_TOOLCHAIN_REPO`) is optional; a checkout is only an offline source for
the same zips. `fetch.ps1 -SaveReleaseAssets <dir>` writes the verified zips to `<dir>\assets\` (the
container build uses this). CI in rvs-decomp downloads the release assets the same way.

## How the minimum set was derived

1. The full toolchain (3,693 files in 8 pieces) was installed with `fetch.ps1` and the last-access time of
   every file was set to 2001.
2. Everything that reads the toolchain was run on it: the CI pipeline (`ci/run.ps1`: every target, all 22
   images, the unresolved-symbol check, then the scorer with an empty `undname` cache so `undname.exe` and
   `msvcr71.dll` are used), the pull-request baseline build of an older commit, and the release steps
   (`rvsbake`, `package.py build|zip|audit`, `tools/script/cibuild.py`, the installer). The files whose
   access time had moved were listed: 632 files, committed as `toolchain/files/read-set.txt` in rvs-decomp
   (regenerated with `toolchain/readset.py`). The release carries the part of that set that has no public
   copy (28 files); the rest of it is fetched from the public sources in the manifest, and the public files
   nothing reads are not in the files lists at all.
3. The trimmed set was installed into a clean directory by `fetch.ps1` and the full pipeline was run again.
   All 22 images are byte-identical to the full-toolchain build except for the linker's timestamps and, in
   `Engine.dll`, the `__TIME__` string (both change on every build), `score.json` is identical, the 21
   `.u` packages are identical under `tools/script/samebuild.py`, and the installer builds.

The zips used to hold whole pieces (31 MB zipped), because they were packed when nothing had a public
source. The manifest used to list all 3,693 files (200 MB installed, 242 MB to download); it now lists the
632 the build reads (70.5 MB installed, 88 MB to download).

## Zip contents and the public sources

Everything that is not in a zip is downloaded from byte-identical public copies, pinned in the manifest:

* `msvc71-3077`: 10 of the compiler and tool binaries from OmniBlade's decomp.me release
  [`msvcwin9x/msvc7.0.tar.gz`](https://github.com/OmniBlade/decomp.me/releases/tag/msvcwin9x),
  the rest from `archaic-msvc/msvc710` and one Civilization IV modding repository that carries the same
  files.
* `vc6sp5pp`: 114 files from OmniBlade's
  [`msvcwin9x/msvc6.5pp.tar.gz`](https://github.com/OmniBlade/decomp.me/releases/tag/msvcwin9x),
  and single files from `archaic-msvc/msvc600_sp5` and `QianNangong/VC6Ultimate`.
* `msvc71`, `winsdk`, `dxsdk`: single files of the `archaic-msvc/msvc710_sp1` commit, of
  `widberg/msvc8.0` (its PlatformSDK tree), and of other public repositories with copies of the same SDK
  files.
* `stlport-4.5.3`: the SourceForge STLport 4.5.3 archive.

The three large commit archives of the full toolchain (`msvc710_sp1`, `msvc600_sp5`, `msvc8.0`) are not
downloaded any more: the few files read from them come one by one from the same commits through
`raw.githubusercontent.com`. Only the three release archives above are downloaded whole, and only their
listed members are extracted.

Each URL, commit and archive hash is in `manifest.json`; `fetch.ps1 -List` prints them.

## Files

* `assets/*.zip`: one archive per piece, identical to the release assets of `toolchain-1`
  (deterministic: fixed timestamps, deflate level 9).
* `manifest.json`: identical to `toolchain/manifest.json` of rvs-decomp. Top level: `release_repo`,
  `release_tag`, `assets_dir`; per piece: `public` (third-party sources) and `release` (this
  repository's zip: `asset`, `sha256`, `size`, `files`, `bytes`).
* `tools/stage.py`: packs `assets/<piece>.zip` and writes the first-generation files lists and manifest
  from a source tree. The current manifest and files lists were refined in rvs-decomp afterwards (more
  public sources per piece), so they are maintained there; `stage.py` packs every non-public file of a piece, whereas the released zips were then trimmed to the
  minimum set above (28 files), so do not use it to repack the release as is.
